# 1.3.4 修复与验证记录（2026-10-27）

基于 v1.3.3（`f0f71d7`）继续检查生产代码，以可复现的结果为依据修复，统一插件版本为 1.3.4。发布 ZIP 保留完整源码、引擎锁文件、AstrBot 原生 Pages 和国际化资源，并附 SHA-256 校验文件。

## 控制与任务

恢复 RPC 尚未返回时收到暂停或急停，旧恢复原先会清除新暂停标记；旧恢复失败也可能重新急停已经成功的新恢复。旧暂停、急停和放弃在异步返回后还可能取消或释放较新的工作。共享入口现在为每次控制记录版本，在异步返回后核验；旧请求不能继续改变当前状态。控制台接收急停、退服时同步使旧请求失效，不必等待后台控制任务开始执行。

目标执行原先将一次 `task.status` 查询故障当作技能失败重试，即使原技能仍在运行也会提交第二批动作。现在短暂故障继续核验同一任务；连续三次查询失败请求取消并结束目标。提交回执丢失、缺少任务号、单步超过 15 分钟时也停止推进，不自动重提同一批。暂停与恢复不能使未知提交重新变得可重放。没有任务号的动作仍可能已在远端执行，取消请求也依赖引擎和连接可用性，本轮不将这些情况报告为远端已取消。

模型计划中显式的数组、字符串、数字或 `null` 参数不再被替换为 `{}` 后执行默认动作；省略参数仍可使用技能默认值。

## 战斗与状态

实体从跟踪表消失只能说明离开视野，不能证明死亡。近战与射箭现在监听选定实体的死亡事件，目标丢失时明确返回未确认击杀。同名实体的死亡不能代替当前目标，死亡动画仍留在跟踪表时也能核验结果。监听随当前动作结束释放，并绑定身体、连接、维度与控制版本。

瞄准、拉弓、攻击、寻路和侧移保留取消结果，装备及异步等待后继续检查控制是否有效。侧移被取消时释放自己按下的方向键；旧动作不得清除新控制的按键。

驱动力实例不再直接引用模块级可变模板，水位和活动列表分别复制，避免一个实例的完成反馈或配置修改影响另一个实例。

控制台把“暂停行动”改为“暂停自主行动”。帮助与 README 说明：暂停长期目标和自主生活时仍可接受人工动作，生存反射可能继续响应；急停会同时停止动作和生存反射。此项只澄清已有行为，不新增权限规则。

## 教训存档

教训库中的坏标签、使用次数、时间及无法编码的字符原先可能使召回崩溃，截断文件还可能被后续写入覆盖。现在逐条验证，保留原始坏档并抢救有效记录；读取受阻、无法留存坏档或全库不可恢复时启用写保护。保存通过同目录临时文件、刷盘和原子替换完成，写入失败保留原文件，并返回未能保存。无法编码的新记录在修改内存前拒绝。

保存失败后有效新记录仍可保留在当前内存中，但没有持久化保证；重载前需排除磁盘、目录权限或损坏存档问题。写保护不会自动覆盖修复原档，需保留备份、处理问题并重载。

## 验证

新增检查都补在已有测试脚本中，自动发现仍为 97 个脚本、81 个离线检查和 16 个服务器脚本。各问题均先复现旧行为，再修复生产实现。

专项验证：插件控制 42 项、WebUI 20 项、目标控制 22 项、目标完成 5 项、引擎控制 85 项、后撤控制 18 项、知识库 32 项、生活循环 34 项通过；行动反馈 13 项与日志规范检查通过。

整套离线初跑耗时 460 秒：78 项通过、1 项失败、2 项环境跳过，0 项未完成。失败脚本为 `test_sleep_control.js`：单独重跑后，在第二次普通运行重新复现 `回基地进屋超时`。成功场景使用 40 毫秒真实预算，进屋检查的 CPU/系统调度耗时可能在入睡前耗尽该预算；生产代码正确拒绝过期请求。相关测试改用受控时钟，保留原 40 毫秒预算、真实进屋检查、未天亮失败与超时保护断言，不修改生产睡眠逻辑。

检查器也改为默认打印失败脚本的完整输出，避免原始失败断言被后续通过信息掩盖。已通过注入早期断言失败、后续多条通过输出的场景核对，退出码继续为非零。

修复后通过检查器单独复测睡眠脚本，22 项场景全部通过，包含额外模拟实际耗尽预算后仍抛出超时、未点击床的反证。因此本轮最终覆盖为 **79 个脚本已通过（含 1 项修复后复测）、2 项环境跳过、无未解决失败或未完成**；并非重新运行整套得到的单次全绿结果。两个跳过脚本是 `check_config.py` 和 `test_tool_binding.py`，当前未配置 `ASTRBOT_DATA`；16 个服务器脚本未运行。

睡眠脚本追加连续普通重复 12 轮、对真实房屋检查注入 CPU 耗时的压力重复 3 轮，全部通过；每轮仍验证实际耗尽预算后的超时拒绝。文档更新后的能力数量核对与最终差异格式检查通过。

统一为 1.3.4 后，发布前再次通过插件契约、能力数量核对、AstrBot 插件加载与原生 Pages 5 项检查。安装包按版本标签的 Git 内容打包，保留隐藏国际化目录并排除工作区运行数据。

本轮没有执行 Minecraft 实服或真实模型长时生存验证。上述结果不能证明开放世界长期存活；从零建田、口粮与留种预算、多种子多个昼夜验收，以及宿主开放 LLM 工具时的身份授权约定仍需继续推进。
