# 1.3.2 更新与验证记录

本轮改善目标指令、采收、地形和网页控制的执行边界，默认 WebUI 改为 AstrBot 官方 Plugin Pages。历史修复与实服链见 [此前生存验证](SURVIVAL_2026-10-02.md)，目标恢复协议见 [GOAL_CONTROL.md](GOAL_CONTROL.md)。

## 原生控制台

页面资源位于 `pages/control/`，本地化名称位于 `.astrbot-plugin/i18n/`。使用 `window.AstrBotPluginPage.ready()`、`apiGet` 与 `apiPost`，后端通过 `context.register_web_api` 注册接口，并使用 `astrbot.api.web` 标准响应。页面不读取管理面板 JWT，也不自行模拟父页面权限。

默认 `enable_webui=true`、`webui_mode=astrbot`。从管理面板插件详情打开控制台；独立 `standalone` 模式继续使用访问令牌与独立监听端口。原生 API 注册失败会输出原因，插件的 Minecraft 功能继续初始化；缺少 Pages 的旧主机可以选择独立模式。卸载只注销本实例接口，旧实例关闭不能注销重载后的新实例。

验证使用本机安装的 AstrBot v4.28.0-beta.1 后端：实际路由鉴权、插件请求对象、页面发现及资源重写通过。浏览器预览使用真实页面 SDK 和受限 iframe、测试状态夹具，检查桌面/手机、亮暗主题、急停回执及免额外令牌。此预览状态不作为 Minecraft 实服证据。原生沙箱禁止弹窗，观战显示可复制的地址。

控制任务取消在首次调度前也立即进入终态，退服等待期间可急停；重复紧急请求不创建重复控制。状态返回全部保留回执，缺失过期回执明确提示并释放等待状态；只有采样时间晚于接收时间的快照才能判定新回执缺失。独立模式退出会中止网络读取，丢弃旧世代的所有响应。

## 目标与生存执行

每次目标规划都有独立世代，所有主人控制边界同步使旧世代失效。正在执行的目标只由一个循环推进；暂停不计入失败次数，恢复先检查实际完成情况。可恢复采集检查点只能来自引擎保存的同身体、连接、维度、技能与参数任务，不能由模型伪造。

`collect` 按库存总目标补缺，直接采集分支保留原子技能数量和矿口。新增复现确认：第三个煤掉落后库存达到总目标、身体仍在地下时暂停，恢复仍调用原返程；修复前会在坑内直接报告完成。合成与狩猎分支不承诺任意副作用都能精确重放。

四类常见作物在选取、接近和挖掘准备时核验成熟状态。收割使用真实掉落，补种使用随身种子或根茎并核验世界方块；数量按补种后的净产出计算。取消到达前服务器已经接受挖掘时，恢复仍会处理补种。搜索作物不借采矿路径下挖。

地形高度不计树叶、树干；普通坡地及树林不应触发地下救援。开放三面山谷需有真实天光和连续安全出口，才覆盖周围较高地形的判断；宽坑、窄井和屋顶仍保留地下/遮蔽证据，未知区块不视为安全。

## 模型用量与持续评测

Token 统一使用提供方报告：显式零值保留，缓存输入计一次，没有报告即未知。统计包含请求次数、已报告/未知、失败/取消和等待时间，按自主行动、规划、侦察、聊天分组。页面提供事实用量，不估算费用。

新增 [真实模型持续生存工具](../dev-tools/survival_eval.py) 使用生产 LifeLoop、ActionAgent、PerceptionAgent 和 EngineClient，以及安装的 AstrBot 模型提供方。模型、服务器、RCON 凭据必须显式配置，不从个人配置中搜集。工具不改世界规则或赠送资源，以新玩家空背包进入正常生存测试服，并输出 JSON 汇总。配置方式见 [开发文档](../dev-tools/README.md)。

开始前保持生活循环关闭和引擎急停，正常生存/空背包核验通过后才启动。后续 `bot.spawn`、死亡、重生、换维度及引擎断开接入生产生命周期，重连会清旧会话计划并解除旧死亡状态；验证失败或取消后仍清理引擎。初始化门闩也防止核验前的点名聊天启动模型动作。

本机未配置显式评测模型，已验证缺失配置输出 SKIP；没有执行真实模型 60 分钟或更长的开放世界实测。当前测试只能证明受测执行链和边界，不能给出长期存活成功率。

## 验证结果

最终默认回归发现 90 个脚本，选择 74 个离线检查，72 项通过、0 失败、0 未完成、2 项跳过，耗时 403 秒。`check_config.py` 与 `test_tool_binding.py` 需要显式 `ASTRBOT_DATA` 来检查已安装插件与真实配置，本机未指定该目录，未将它们算作通过；其它检查使用已安装 AstrBot 的解释器与 `ASTRBOT_APP`。

| 范围 | 结果与证据 |
|---|---|
| 原生 Pages | 5 项：官方路由鉴权、页面发现、资源重写、原生请求与接口生命周期 |
| HTTP 与页面会话 | 20 项后端 + 5 个前端场景：提前取消、紧急请求、回执保留、旧会话响应与原生 bridge |
| 目标控制与续采 | 17 项目标控制、36 项插件控制、12 项实际引擎续采检查点，含煤/圆石 collect 的部分采集与采齐后暂停、原矿口返程、旧检查点复制隔离 |
| 成熟作物与地形 | 31 项离线故障注入；返程 44 项、下降安全 52 项复查通过 |
| 模型与评测 | Token 62 项、ActionAgent 48 项、GameAgent 12 项、侦察 4 项、评测接线/生命周期/汇总 19 项 |

离线回归由 `dev-tools/run_all.py` 自动发现与分类；Python 实服脚本的 `Rcon.from_dir` 标记也纳入服务器识别。本轮没有整套运行所有服务器脚本。
