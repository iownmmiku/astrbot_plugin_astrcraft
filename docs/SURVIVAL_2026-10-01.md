# 生存逻辑与连续行动优化（2026-10-01）

这次把生存提醒落实到决策与执行：需要吃饭、恢复生命或腾出采集空间时，先处理当前需求，再接回原计划。

## 行为变化

- 连续计划每一步开始前读取真实背包、血量与饱食度。饱食度不高于 10，或受伤且不足以回血时，优先补给；危险血量且已吃饱时短暂恢复。正常衔接不增加模型调用。
- 补给插步保留剩余计划；补给反复失败则放弃旧路线、重新观察。取快照期间发生急停、玩家插话或重连时，丢弃旧插步。零血量、零饱食度不会再被默认值改成 20。
- 做饭先利用小麦和现有生食。做面包缺工作台时，只补必要木材与工作台；烹饪只处理当前缺少的份数。需要打猎时按可见动物选择目标，不为不存在的牛、猪逐一长途搜索；没有材料或动物则如实返回失败，让模型探索其他来源。
- 饥饿接近危险且有安全生食时先吃现有食物救急。进食必须得到服务端饱食度增加的确认；食物耗尽时返回实际恢复量和是否达到目标。
- 受伤后反射层会更早进食；残血且附近有怪时，紧急后撤优先于吃饭，并可抢占长任务。健康时优先普通食物，保留金苹果作应急补给。
- 背包快满时，采集计划先整理再继续。默认存箱保留工具、护甲、食物、火把等用品；明确指定要存的物品仍尊重调用参数。没有实际存入物品不能报成功。
- 开荒先做一把必要的镐，减少即将淘汰的木工具消耗；金镐不会被判断成铁镐的升级。已有铁矿先熔炼，已有铁锭先升级铁镐。家具放下后不在背包里，不再据此断言屋里没有床或箱子。
- 任务结果优先按引擎提供的技能标识记录，避免「合成物品」「进食补给」等显示名称导致失败记忆错位。

## 验证

默认离线检查：42 个脚本通过，0 失败、0 超时/异常，4 个环境项跳过；另有 8 个服务器脚本不属于该次离线运行。检查包括生存优先级、计划保留、旧快照丢弃、服务端进食确认、后撤优先级、做饭与存箱策略。

项目 Paper 1.20.1 测试服上，通过实际 AstrBot 工具注册、ActionAgent、LifeLoop 与 Node 引擎验证：

1. 饱食度实际降到 0，只提供小麦，关闭自动吃饭以单独验证生活循环。
2. 一次固定模型计划本来只安排砍树、做木镐、挖圆石。
3. 生活循环自动插入做饭：采集必要木材、做工作台、合成 4 个面包，再吃到饱食度 20。
4. 接回原三步计划，实际获得木镐与圆石。全程模型调用 1 次，四处步骤衔接均低于 0.001 秒。
5. 另验证已有 2 条生鲑鱼被烤熟；默认存箱后石镐、4 个面包、2 条熟鲑鱼仍在背包，16 个圆石实际在箱内。
6. 急停和恢复检查通过；测试结束恢复服务器原难度并退出测试机器人。

测试命令：`python dev-tools/test_autonomy_live.py --agent --survival --supplies`。
结果日志位于本地 `.testserver/optimize-autonomy-final.log` 与 `.testserver/optimize-offline-final.log`。

模型回复固定用于隔离执行逻辑；这些结果不代表真实模型已在开放世界长期生存验证通过。紧急后撤、回血策略的新增边界由离线真实实现测试覆盖，敌对环境中的长期表现仍需继续实测。

## 启用

重载 AstrBot 插件，使 Python 与 `engine/` 同时使用更新后的代码。保持 `enable_life_loop` 开启；`mc状态`、`mc诊断` 可查看当前任务与停牌原因。`mc急停` 持续暂停，`mc继续` 恢复。
