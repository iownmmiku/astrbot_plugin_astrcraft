# 自主游玩修复记录

对应 [修复前检查报告](REVIEW_2026-09-30.md)，基线提交 `7ab5271`。
目标是让现有决策、计划、动作与反馈持续运转，按照实际背包完成生存任务。

## 已修改的行为

| 检查项 | 修复 |
|---|---|
| 1、2：决策故障与技能退避停住循环 | 模型失败后按 8 / 30 / 60 / 120 秒自动重试，成功清除故障；同一批技能失败只触发一次退避，新指令可唤醒重新规划 |
| 3、5：取消后的旧动作与重复队列 | 停止底层挖掘、进食和移动；取消后旧异步执行不能重新取得身体控制；单次提交只入队一次 |
| 4、6、8：生存反射 | 使用 mineflayer 的实际氧气字段；空手先装备食物；普通反射去重且执行前重新确认需求，致命危险可抢占 |
| 7：急停 | Python 生活循环、目标与 Node 身体/反射保持暂停；任务完成、进服和引擎重启不会解除；`mc继续` 显式恢复 |
| 9、10：取物与前往玩家 | 无坐标取物自动寻找附近容器；前往玩家到达即完成，后续任务继续执行 |
| 11：手动退服 | 自动连接监管尊重手动退服，显式进服才解除 |
| 12、13：攻略和教训 | 攻略仅允许登记且解析后仍在攻略目录的文件；教训去重保留不同矿石、工具、数量和关键顺序 |
| 14：测试误报全绿 | 失败、超时和启动错误都返回非零；历史偶发记录不能豁免失败 |

集成复核中进一步修复：

- 正常行动代理缺失生存建议；现在使用实际顾问输出并加载技能白名单。
- 计划提交后结束模型回合，避免同一回复又计划又直接动手；完成通知马上推进后续步骤。
- 完成事件先于 RPC 应答到达时，旧请求不会重新压上 8 秒等待。
- 普通完成通知保留计划；新指令、受伤和工具损坏在步骤边界重新规划。
- 游戏聊天串行等待，不丢后续消息；点名指令只有一个执行者，动作尝试后回复失败也不会整条重放。
- 玩家新计划替换旧自主计划；反射完成不会解除玩家动作的暂停，反射取消不会被当作计划失败。
- 插件卸载取消延迟绑定、自动连接和游戏回复，旧实例不再继续操作。
- 工作站目录接入插件数据目录，供引擎跨启动保存箱子、熔炉和工作台位置。
- 木板、木棍和工具按实际产出数量与配方成本补料，已有物资和工具不会重复消耗；合成每一批等待窗口与背包确认。
- 容器关闭和搬动物品的异步续段也受取消约束；旧窗口不能关闭新窗口或覆盖新背包槽位。
- 多步计划可通过 JSON 数组携带每步数量、工具层级等参数，原有逗号/换行技能名格式继续可用。
- 重连清空活跃与待执行计划，丢弃重连前仍在等待的模型回复或动作，保持急停。
- 设置长期目标期间保留身体控制权；旧任务完成和晚到的旧目标通知不能恢复自主循环。命令和模型工具使用相同控制逻辑。
- 庇护所按实际缺格补齐建材，门预留六块同种木板；必须验收完整地板、墙、屋顶和上下两格门才报告成功。家具标记也读取实际世界。
- 进服、重生、受伤、动作完成与断线使状态简报失效；事件发生期间返回的旧 RPC 不能重新覆盖新状态。
- 死亡状态在异步通知前记录，重生等待服务器恢复生命后解除死亡停牌；恢复清单和主人急停仍保留。
- 寻路脱困后重设原目标，取消时停止旧脱困；立即清空旧路径，避免寻路库延迟停止误取消下一条路径；实际进入请求位置可立即结束，未到达的结果不能报告任务完成。
- 新协议合成逐次同步点击，排空迟到的窗口纠正；收取服务器实际计算的配方结果，避免按钮误产出、少产出和重复消耗材料。
- 工作台放置避开火把、门等占用格；庇护所优先完整平地，避开已有家具，在地基外取材，回屋内施工；建材耗尽时同一格切换到剩余材料，按实际使用记录消耗。
- 深井必须实际站到井口才算脱困。窄井优先原地垫高，起跳前装备方块，身体离开目标格再立即放置，并在落地后验证高度与支撑；本轮 10 格深井爬升约 9 秒。
- 挖台阶时保持站位，单格爬升不再使用长距离分段兜底或延迟停止；采矿脱困预留要求的产物，避免刚挖出的圆石全部用于垫高。
- 完工后的进屋和家具操作禁止寻路自动挖墙，限制显式传到原生事件回调；一次被状态纠正拒绝的合成收料点击可以同步后重试，连续三次无进展则如实失败。
- 脱困测试按真实井口与任务状态验收，每个场景清空背包，深井垫高使用独立新井；分步测试执行零项检查会失败。移除基于旧错误断言统计的深井“偶发率”。

## 验证方法

新增离线回归覆盖恢复、暂停所有权、队列取消、反射、工具协议和路径边界。
使用本机实际 AstrBot Python 运行时与 Node 依赖执行，连接项目 Paper 1.20.1 测试服验证游戏动作。

`test_autonomy_live.py` 使用真实 LifeLoop、插件状态适配器、EngineClient 和 Node 技能：
从空背包砍树，合成木镐，再挖圆石，核对真实背包产物与步骤衔接耗时，并验证急停/恢复。
默认模式使用 JSON 决策；`--agent` 使用实际 ActionAgent、AstrBot 工具注册表和 `mc_plan_do`。
两种模式的模型回复均固定为一份三步计划，以隔离检查执行链；这不是实际模型在开放世界中的长期评测。

跳过项主要依赖已安装插件的 `ASTRBOT_DATA`，以及默认未启用真实进服的集成模式；
集成测试已另行打开进服与死亡参数运行。Windows 无符号链接权限时，工具协议测试中的一项链接越界用例明确跳过。

真实测试使用专用 Paper 1.20.1 生存测试服，并通过 RCON 准备地形和补充材料。
这些结果确认当前执行链与受测动作能运转，不表示已完成真实模型在开放世界中的长期稳定性评测。
采矿返回地面和复杂地形脱困仍可能花较长时间；模型策略、敌对环境、模组服与长距离探索需继续按实际场景验证。

## 使用

更新代码后重载 AstrBot 插件，确认引擎使用本项目的 `engine/`。
保持 `enable_life_loop` 开启（默认开启），进服即可启动自主生活；`mc状态` / `mc诊断` 可查看当前动作、故障和重试期限。
`mc急停` 持续暂停所有行动，`mc继续` 恢复。

复杂地形寻路、坠落自救、正版登录和模组服的边界仍见 README；本次修复不表示已完成所有开放世界玩法。
