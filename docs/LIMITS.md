# 能力边界：哪些真能像玩家，哪些不能

这份文档存在的意义是**避免过度承诺**。下面每一条都对应代码里的具体实现或限制，
不是估计。

---

## 能做的（已实测）

| 能力 | 实现方式 | 实测结论 |
|---|---|---|
| 真实物理移动 | mineflayer + prismarine-physics | 走 24.7 格、落点误差 0.7 格、耗时 5.1 秒；上下台阶由物理驱动，不是瞬移 |
| A* 寻路绕障 | mineflayer-pathfinder | 能绕开障碍、跳下 3 格内落差；找不到路时诚实报错 |
| 破坏方块 | 真实挖掘时长 + 工具判定 | 工具不对会明确说"需要一把镐"；挖掘后自动捡掉落物并报告获得物 |
| 合成 | 配方表查询 + 自动找/放工作台 | 能完成 原木→木板→木棍→工作台→工具 的完整依赖链 |
| 熔炼 | 熔炉交互 + 燃料管理 | 自动补熔炉、自动找燃料、等产物出炉 |
| 背包与容器 | 存取箱子、丢弃物品 | 支持 list / put / take |
| 战斗 | 装备武器 + 攻击冷却 | 会追打、血量低会撤退；打不过会如实报告 |
| 进食 | 按营养价值选食物 | 饱食度低自动吃，不需要 LLM 介入 |
| 建造 | 依附面放置 + 逐层砌墙 | 能盖出有墙/屋顶/门/火把的小屋，位置与材料会验证 |
| 感知 | 状态快照 + 差分事件 | 位置、血量、饱食、背包、附近实体、脚下/光照、时间天气 |
| 长期目标 | 技能链 + 失败重试 + 降级 | "挖 10 个铁矿"这类目标能自主推进，卡住会说卡在哪 |
| 双向聊天 | 事件桥 + 人格化回复 | 游戏内聊天转发到 QQ/TG；提到机器人名字它会接话 |

## 做不到的（明确不支持）

| 不支持 | 原因 | 影响 |
|---|---|---|
| **Forge / Fabric 模组服** | mineflayer 需要模组注册表与握手适配，工作量大且随模组变化 | 只能进原版 / Paper / Spigot 类服务端 |
| **正版（Microsoft 账号）登录** | 默认走离线账号；正版需要 `prismarine-auth` 设备码授权与凭据缓存 | 默认只能进 `online-mode=false` 的服务器。配置方法见 SETUP.md，但**本次未端到端验证** |
| **识别游戏画面** | 用结构化状态而不是截图 | 看不懂告示牌文字、地图画、玩家皮肤；不做"看图找路" |
| **跨维度行动** | 未实现传送门/传送指令 | 不能自己下界或去末地 |
| **附魔 / 药水 / 酿造** | 未实现附魔台与酿造台交互 | 只能做出无附魔的工具护甲 |
| **红石精密操作** | 未实现高频方块交互 | 能按按钮/拉杆，不能搭红石电路 |
| **村民交易** | 未实现交易界面 | 只能打村民（不推荐） |
| **多人协同** | 单机器人设计 | 不支持多个机器人协作分工 |
| **精细建筑** | 建造技能只做"能住的小屋" | 不能照图纸盖大型建筑 |
| **自然语言理解全部口语** | 目标解析靠模板 + LLM 兜底 | 「砍点木头」能懂；过于含糊的说法会要求澄清 |

## 可能不稳定的情况

| 场景 | 表现 | 应对 |
|---|---|---|
| **复杂地形下的长距离寻路** | 在主世界的丛林/起伏地形中，出现过"寻路立刻报找不到路径、原地不动" | 同一套代码在超平坦世界稳定通过（24.7 格、误差 0.7 格），说明是地形相关限制。引擎会**如实报错并说明可能原因**，不会假装到达。可尝试拆成多段短距离移动，或先挖开挡路的方块 |
| **严重反作弊**（Grim / Vulcan / 严格配置的 NCP） | 可能因移动模式被判定异常而踢出或回弹 | 打开 `slow_mode`（降速、关跑酷）。仍不稳定则说明该服务器的反作弊不接受自动客户端，属于能力边界外 |
| **出生在树冠/水面上** | 会先尝试破叶子下到地面；落点不佳时可能耗时较长 | 已在 `skills/common.js` 实现；超大丛林里下降会分段进行 |
| **完全封闭的空间** | 寻路报"找不到路径" | 需要 LLM 或用户指示"挖开挡路的方块"，引擎不会自己拆墙（因为真玩家不会） |
| **服务器 TPS 低 / 正在生成大量区块** | 动作确认变慢；**传送到未生成的冷区块时，服务端会静默忽略我们的窗口点击**（合成会失败） | 客户端超时已放宽到 180 秒 + 指数退避重连；心跳只在空闲时发（**实测连续 4.5 分钟静置不断线**）。合成侧有 3 轮"复位重试"兜底 |
| **合成偶发失败** | 约 1/6 的运行里，**合成工作台**这一步会失败（4 个物品的 2×2 配方，点击次数最多） | 见 `ACCEPTANCE.md` C4 节：已修 6 个真问题（合成格残留、窗口状态不同步、多产出配方算料、超时误译等）。失败时**如实报错**，不会假装成功；重试机制吸收了大部分瞬时故障。这是 mineflayer↔服务端窗口状态机的固有脆弱点，属能力边界内的已知不稳定 |
| **领地保护插件** | 破坏被拒绝 | 配置 `dig_blacklist`，或接受"这个区域动不了" |
| **深层矿脉长时间挖矿** | 已实测"造矿脉 → 挖矿 → 熔炼成锭 → 做铁镐"**整条链 13/13 全过**（挖 6 个铁矿 8.8 秒、熔炼 43 秒、做铁镐 2 秒）；**未在真实深层矿洞里长时间跑** | 实现已完成（工具依赖、向下挖阶梯、安全判断），建议先在自建服上试跑 |
| **陡坡 / 山顶出生** | 若出生点在陡峭山坡的窄台上（一侧岩壁、一侧断崖），**完全没有可走的方向**——实测"移动 0.0 格"。现在会尝试**朝岩壁挖进去**（跳 → 挪 → 挖墙），但若四周都是不可挖的方块（领地保护/基岩）就只能如实报错 | 她仍能挖矿、盖房（都实测通过）；`engine_check` 里"笔直走到 15 格外的固定坐标"在陡坡上不可靠 |
| **测试用世界会被测试自己挖坏** | 冒烟测试会从脚下挖 3 格，洞留在出生点；历次运行会把出生点挖到基岩，下次运行机器人掉进坑底、寻路全灭——**看起来像代码坏了，其实是环境脏了** | 给 `tools/smoke.js` 传 `MC_RCON_PORT`/`MC_RCON_DIR` 即开启"开局复位 + 挖完填回"，测试可重复。**跑测试时建议都带上** |
| **自己挖的矿道回地表** | 已实现 `climbToSurface`（挖阶梯向上），实测能脱困；但**在垂直竖井里**需要多轮尝试 | 现在的下挖默认走**阶梯**（可原路走回），竖井只在阶梯挖不动时作为兜底 |
| **火把位置** | 庇护所的火把有时插不上（位置被屋顶/墙占住），会记录为**非致命失败** | 小屋的墙、屋顶、门都能建成；火把是可选装饰，失败不影响"能过夜" |
| **主动生存的完整度** | 实测：**砍树 ✅ 挖石头 ✅ 做石制工具 ✅ 盖庇护所（含门）✅**；决策层现在有"生存阶段"概念（`plugin/advisor.py`）与失败记忆，不会再在同一个失败上循环一小时 | 她会自己按阶段决策并真的动手；若某个地形反复失败，日志里能看到具体原因，不会假装成功 |
| **生存顾问的规则边界** | 顾问是按"阶段"给建议的规则（木头→工具→石头→住处→铁矿），**不覆盖开放玩法**（比如你想让它专心养动物或造景观） | 决策权仍在 LLM，顾问只是把"缺什么、下一步该做什么"摆到它面前；阶段建议可被 LLM 覆盖（除前置条件缺失时） |
| **工具耐久** | 木镐只有 59 耐久，会在挖矿中途碎掉；现在会**自动用圆石换石镐**，但若当时没有圆石就只能等它碎 | 建议给机器人备料，或让它先执行 `make_tools` |

## 安全边界（默认值）

- 不挖 `bedrock` / `barrier` / `command_block`
- `spawn_protection_radius` 默认 0（不额外保护），可设为正值开启出生点保护
- 挖掘白名单默认空（不限制）；生产环境建议显式配置 `dig_whitelist`
- 不主动攻击玩家（只打生物）
- 说话有 10 秒 5 条的限流，避免被服务器判刷屏
- `/mc急停` 立刻停止所有动作；LLM 工具在机器人未进服时直接拒绝执行

## 资源占用

- Node 引擎常驻进程：空载约 80–150 MB 内存
- 加载 5×5 区块时会有明显峰值；`view-distance` 越大占用越高
- 每个技能任务的日志与进度都在内存里滚动保留最近 50 条，不会无限增长

## MLG 排查记录（落地水为什么救不了命）

这条路径查了很多轮，把**每个环节的实测证据**留在这里，免得重复踩。

### 已经修好的（都有实测）

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| 1 | **`entity.velocity` 不可信** | 她坠落 18 格时该值只有 **-0.078**，而阈值是 -0.7 → MLG **一次都没触发** | 改用**位置变化率**（实测 12~36 格/秒，判断准确） |
| 2 | **动作窗口太窄** | 坠落 23 格/秒 → 3~5 格窗口只有 90ms，而检查间隔 100ms | 窗口放宽到 7 格 + 坠落时插两次 33ms 检查 |
| 3 | **`place(reach:true)` 会寻路（15 秒超时）** | 人正在坠落，第一次尝试就卡 15 秒，`_mlgRunning` 一直为 true | 改成 `reach:false` + 400ms 硬超时 |
| 4 | **`_currentReflexRunning` 把它挡在门外** | MLG 是最高优先级本能，却被"反射层正在跑"挡住 | 去掉这个门控 |
| 5 | **包发错了** | 逐个包实测：水桶只有 `activateItem`（`use_item` 包）能让服务端倒出水；`activateBlock`（`block_place`）**桶永远不会变空** | 按"是不是方块物品"分派 |

### 仍然做不到的

**高速下坠中，服务端经常拒绝这次"使用物品"**。证据：

```
坠落中 MLG 诊断: holdItem ok → lookAt ok（pitch=-1.57）→ activateItem 已发
                 → 但脚下没水（那里是 air）
背包: {"water_bucket":2}     ← 桶没变空桶，服务端拒绝了这次使用
落地血量 6.5/20
```

对照实验（**站在地上**、或**慢速下落**时倒水）是**成功**的：桶 8→7、空桶 0→1、
世界里出现 49 格水。所以不是包错了，是**时机**。

在 1 格宽竖井里重复 3 次，其中 1 次出现了空桶（说明偶尔成功），但水没有留在落点。

### 结论与替代方案

**"错过一秒就必死"的补救型自救，在这类服务端上不可靠。**
真正管用的是**提前预防**，已经实现并验证：

- **走路时的悬崖保护**：`stepToward` 每走一步先看前方落差，超过 3 格就停住
  （实测：朝悬崖走 16 格，她停在边缘，血量 20/20，下降 0 格）
- **动手前的危险扫描**：`mc_check_danger` 报出附近的岩浆、深水、悬崖
- **下矿走阶梯**：默认挖阶梯而不是竖井，能原路走回来

也就是说：**这条能力的价值从"掉下去之后自救"转成了"根本不掉下去"**。

## "乱走乱挖"的排查记录（T2）

用户反馈"很多无意义的动作、乱走乱挖"。逐个查过，结论分三块：

### 一、反射层没有乱动来源（已逐个审计）

会"动她"的本能一共 10 个，全部是合理反应：
脱困 / 溺水上浮 / 岩浆 / 着火找水 / 进食 / 低血后撤 / 反击 / 捡掉落物 / 插火把 / 做火把。
其中"捡掉落物""插火把"**只在完全没有任务时**才做。

### 二、真正的来源是"模型微观管理"（已修）

`task.finished` 会**立刻唤醒**她继续想，而模型用**短动作**干活时
（一次 `mc_goto` / `mc_craft` 一两秒就完），决策节奏变成**每几秒一次**，
每决策一次就可能改主意 —— 玩家看到的就是"她一直在乱走、换个没完"。

**两处修**：
- **承诺机制**（`life_min_decide_gap`，默认 6 秒）：两次决策之间有最小间隔
- **技能承担多步**（见 T4）：提示词原来让模型调一个**不存在的工具**
  （`mc_skill_run`），现在改成真实工具名 + 代码里强制"提交长任务就结束这一轮"

### 三、"蹭掉软植被"比想象的小得多（实测）

- 走 18 格穿过软植被：只有 5 个被弄没（而且不是树叶）
- **决定性实验**：铺 60 格密集树叶墙让她穿过去
  → **直接穿过去了，树叶一格没挖**（60 → 60）

原因：草和树叶的 `bounding_box` 是 `empty`，pathfinder 直接把她送过去，
不需要挖。"乱挖"的嫌疑比我以为的小得多。
