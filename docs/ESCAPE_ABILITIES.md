# 她缺的三个"脱困能力"（用户反馈，2026-09-21）

> 用户原话：**"她好像没有铺路，挖掘挡路的方块，以及从地下垫上来的能力"**
>
> 核对结论：**三件事全都没有**（或者只藏在内部、她调不到）。这是"她卡住不动"的根本原因。

---

## 一、核对结果（有证据）

| 能力 | 现状 | 证据 |
|---|---|---|
| **从地下垫上来 / 爬出坑** | 代码**有**，但她**调不到** | `skills/common.js` 的 `climbToSurface`（含垫脚上升 + 开侧洞 + 挖阶梯）**只被三处内部调用**：`wood.js:40`（chop_tree 开头）、`building.js:41`（build_shelter 开头）、`bot.js:909`（脱困反射第 4 次起）。**没有注册成技能，也没有对应的 `mc_*` 工具。** |
| **铺路 / 搭桥** | **完全没有** | 只有 `mc_place`（放一格）。没有"往前垫一串方块跨过坑"或"垫高自己"的可调用能力。 |
| **挖掘挡路的方块** | **只有一次一格** | `mc_plan_route` **只描述**要挖哪几格（"要挖 stone×3、要垫 cobblestone×1"），真正挖掘要靠 `mc_mine` 逐格。而 `MAX_STEPS=6`，一轮最多挖几格。 |

## 二、为什么这会导致"她站着不动"

她现在**没有"故意"脱困的手段**。唯一的出路是**脱困反射**（`_reflexTick` 里的 autoUnstuck），
而它是：

- **自动的**（她自己不能主动触发）
- 带 **8 秒节流** + **2 秒二次确认**
- **5 次失败就降频**（W7 之后是 60 秒一次）
- 而且只在"被方块占住身体 / 四面围死"时才触发

所以当她掉进一个 **2 格深的洼地**（MC 跳跃高度 1.25 格 → 跳不上去；而"走路不改动世界"→ 普通移动也不挖），
她从自己的视角看就是：**反复尝试走近目标 → 反复失败 → 距离始终 5 格** ✗

**实测复现**：

```
1 格深的坑: ✅ 出来了
2 格深的坑: ❌ 出不来（原地不动）
3 格深的坑: ❌ 出不来（原地不动）
```

日志里她当时学到的教训也印证了这一点：
- `砍树时若距目标原木仍有5格够不到，先垫方块或绕到相邻可站立位`
- `目标在自身 y 上方且寻路连续失败时，别重复走，改用 mc_...`

**她知道该垫方块——但她没有那个能力。**

## 三、要补的三个能力

### 1. `climb_out`（爬出来）—— 最高优先，代码已经存在

把 `climbToSurface` 暴露成一个技能 + `mc_climb_out` 工具。
参数：`max_steps`（默认 24）。

**为什么排第一**：代码已经写好并验证过（竖井 20 格能自己爬出来），
只是**没有入口**。这是"投入最小、收益最大"的一个。

### 2. `pave`（铺路 / 垫高）

两个方向合一：

- **水平铺路**：往指定方向逐格放方块，跨过坑/岩浆/水，或者填出一条路
- **垂直垫高**：往自己脚下放方块把自己垫上去（`climbToSurface` 里的 `pillarUpOne` 已经实现了这个动作，
  抽出来复用）

参数：`direction`（forward/up）、`count`（默认 4）、`item`（可选，不指定就自己挑）。

**注意**：垫脚上升必须"跳起来、等真的离地 0.7 格以上、趁空中往脚下放"——
这是实测踩过的坑（站在地上放会被服务端拒绝："the block is still there"）。

### 3. `dig_path`（挖通）

把 `mc_plan_route` 说的那几格**真的挖掉**：给定目标，规划路线 → 挖掉挡路的方块 → 走过去。
参数：`x`/`y`/`z`（目标）、`max_blocks`（默认 8，防止她一次挖穿半座山）。

**为什么需要**：现在"看路线"和"真的挖"是两件事，而后者要一格一格调 `mc_mine` ✗
一轮 6 步最多挖几格，所以她**永远挖不通一条路** ✗

## 四、顺带要改的：失败信息要说清病因

`move.to` 失败时现在说：

```
可能被方块挡住或目标不可达；可以试试先挖开挡路的东西，或换一个更近的位置
```

**它没告诉她"你比周围地面低 2 格、跳不上去、得垫方块或挖台阶"** ✗
这和之前治过的"走不到只说水平距离"是同一类病（报错误导 → 反复重试）✗

改：失败时检测"我比周围地面低几格"，低 ≥2 格就明说：
**"我掉在坑里了（比周围地面低 N 格），跳不上去，得用 mc_climb_out 或者垫方块"** ✓

## 五、完成定义（和之前一样，不打折）

每个能力都要：实现 + 实测验证（新增测试，跑通）+ 全量回归 + 同步三处 + 推送 GitHub。

**顺序**：`climb_out`（代码已有）→ 失败信息（小）→ `pave` → `dig_path`（最大）。
