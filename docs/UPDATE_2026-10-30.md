# v1.3.5 优化、修复与验证记录（2026-10-30）

本版基于 v1.3.4（`938b8fd`），汇总此后的本地优化与修复，版本统一为 1.3.5。本记录保留完整初跑和对应复测结果，验证范围仍为本地离线检查。

## 行程预算与成长方向

我用同一份 `engine/survival_budget.json` 连接 Python 决策与 Node 执行，按近处工作、远行和采矿区分口粮、火把、燃料与垫脚材料储备。工作交接时先处理可完成的补给，再接回原步骤；没有明确粮源时，不把预备粮变成无限找食物。默认存箱按数量保留，并留下种子、有限铁料和按耐久选择的工具，人工明确指定的物品仍使用原有语义。

交叉复审补上远方/连续失败箱子的补给门槛，以及路上、开窗等待和换箱后物品变化的实时预算。同名工具按具体源槽位转移，避免旧版空 NBT 匹配或新版 components 耐久信息被忽略时误存好工具。

顾问的普通铁料目标为十六，满足后转向农田维护、食物储备与基地附近探索。探索半径限制为 8–32 格，只走已加载安全落点，不挖垫开路，每次只尝试一个目标且导航最多十五秒，近期失败落点不会立即重复。该规则不限制主人明确指定的采集数量，也不宣称能自动完成远征。

## 基地小麦田

我加入 `tend_farm`，在当前世界基地附近已有天然静止水源旁维护最多八格小麦田。没有种子时有限打草取种，没有锄头时用现成木料制作；耕地、播种、收割与补种都核验实际物品和服务端方块。保护基地结构及过道，不搬水、不远行找材料，未知光照和不安全站位不作为可用地块。

农田部分成果按服务器、维度与基地原点保存，下次按实际方块恢复。成熟后收割并补种，未成熟先做其他工作，不占着任务等待生长。只读扫描每次最多 2048 次方块读取，已记录田地优先检查，未完成扫描不误报没有水源。

联调补上有限留种：新播种不消耗最后一粒备用种，成熟作物缺少种子掉落时保留实物和空耕地，报告补种未完成；只有一粒种子且无成熟田、无已知草丛时，不重复触发建田。

## 观察与控制台

我把身体、背包、基地与农田合并为一个同步引擎观察，并在 Python 侧合并仍在进行的重复请求；完成后的后续观察重新读取，取消某个读取者不取消其他读取者。身体、世界或物品变化后丢弃迟到结果，并在有效性检查之后才更新基地记忆。基地或农田检查失败只影响各自状态，血量和物品仍可返回。

原生 AstrBot Pages 与独立控制台共用等待说明：实际继续条件、已有重试时间、失败次数与本次预算。引擎发出真实任务开始事件，用最近一百个有效样本计算状态读取和连续技能交接的 P95；失败结果、人工动作、暂停及无后续计划的空闲不会作为成功技能衔接。这里减少了观察往返，尚未测得真实服务器和模型下的速度提升。

本地只读模拟预览检查了桌面与 390 像素宽视口：等待说明能够换行，预算及未知指标正常显示，没有横向溢出。会话/bridge 的自动化检查另验证退出后清空状态和迟到响应隔离；预览不等同于已安装 AstrBot 面板的端到端验收。

## 生存验收工具

我把评测运行结束与基准通过分开，新增通过、失败和证据不足三种结论。默认基础档要求有效观察时间、连续昼夜、零死亡和人工干预、有限饥饿比例、真实工具与住所、普通食物净增长以及足够的技能交接样本。阈值可在运行前配置，并写入报告；不根据成绩自动放宽。

多种子汇总核对种子、构建与模型指纹，默认要求三个种子各两轮，重复报告不增加轮数。这里只验证报告、接线与判定逻辑，未生成任何真实生存达标结论。运行方式和具体边界见 [开发工具说明](../dev-tools/README.md)。

## 自主计划

自主生活与行动代理留下的计划现在共用完整校验。未知技能、畸形步骤、非对象参数及超过六步的计划整体拒绝，不再跳过前置步骤、截断尾部或把错误参数替换成默认参数。拒绝时保留已有有效计划，省略参数与字符串技能步骤仍兼容。

模型反复坚持失败动作、改由顾问替换首步时，同时清除依赖原首步的尾部，下一轮依据实际结果重新安排。二次思考期间主人更新计划后，迟到的模型结果在解析前检查计划版本，不能再覆盖新计划。

## 引擎生命周期

并发启动等待同一次真实就绪，尚未收到 `engine.ready` 时不能提前成功。停止使已经等待启动锁的请求一并失效；停止后显式发起的新启动仍然允许。进程创建晚于停止返回时回收该进程，等待就绪时取消也负责关闭自己的进程。

标准输出和错误输出绑定原进程。旧进程的迟到就绪信息不能替换新状态，旧通道结束不能使新进程的 RPC 失败或误报新连接断开。启动诊断清除上一进程的错误日志，缺少依赖的提示统一使用锁文件安装命令。

## 工作站存档

工作台、炉子、容器和床的位置存档逐条校验，并在抢救有效记录时保留原始坏档。整档不可恢复、文件不可读或坏档无法留存时启用写保护，不让后续自动记录覆盖原档。不支持的新版本格式同样保留。

保存使用同目录临时文件、刷盘和原子替换；写入、刷盘或替换失败保留旧文件，清理临时文件并记录未保存。写保护或保存失败时，新位置仍可用于当前进程，但不承诺重启后保留。记录只装载已知字段，避免存档中多余的 `kind` 改变位置类型。
