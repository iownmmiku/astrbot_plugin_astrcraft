# Astrcraft

**让 AstrBot 的机器人在 Minecraft 里像一个真玩家那样自己过日子。**

不是"会聊天的 NPC"，也不是"瞬移 + 秒破方块"的脚本。它是个服务端眼里的**真实玩家**：
原版物理、区块解析、背包/合成/熔炼，每个动作都由服务端逐条校验——
和红石、怪物 AI、别人的建筑站在同一套规则里。

```
你：    砍点木头回来，顺便做个工作台
Astrcraft：嗯，这就去。
        ▸ 砍树 ×8 → 木板 ×16 → 工作台 → 放下 → 木棍 ×4 → 木镐
Astrcraft：木头砍够了，工作台也摆好了，镐子也顺手做了。
```

## 它能做什么

| | |
|---|---|
| ⛏️ **干活** | 砍树、挖矿（找矿脉）、采集、合成、熔炼、把战利品塞进箱子 |
| 🏠 **盖房子** | **照着图纸盖**——图纸由模型自己画（字符网格 + 调色板），能盖出有窗、有屋檐、有隔断的房子，而不是只会盖方盒子 |
| 🧭 **走位** | 真寻路：绕障碍、上下台阶、跳下落地、**走路不改动世界**；走不通时列出"要挖哪几格、要不要垫脚"的候选路线，由模型决定值不值得动世界 |
| ⚔️ **战斗** | 近战、躲怪、快淹死自己上浮、血量低了自己后撤 |
| 🔭 **感知** | 扫方块、扫实体、查状态、查配方、看世界时间与天气、**动手前先扫一遍附近有没有岩浆/悬崖** |
| 🍞 **过日子** | 饿了吃、没吃的去打猎、天黑了点灯、晚上回屋、从高处坠落会自救 |
| 🧠 **会积累经验** | 攻略（人写的）+ **教训（它自己从失败里总结的）** + 世界笔记；同一个坑摔三次就会记下"下次该怎么做" |
| 🗺️ **会记路** | 记住用过的箱子/熔炉/工作台在哪，下次直接走回去用，而不是重做一个 |
| 💬 **聊天** | 游戏内聊天转发到 QQ/TG；游戏里提到它的名字，它会用人格接话 |

**LLM 是真的在控制它**：50 多个工具（移动 / 挖掘 / 放置 / 战斗 / 合成 / 扫描 / 容器 / 图纸…），
模型一步步决定做什么；工具返回什么就读懂什么，换个做法再来。

## 快速开始

### 1. 装插件

**可以直接把整个仓库克隆进插件目录**（仓库根目录就是插件本体，`metadata.yaml` / `main.py` 都在根上）：

```bash
cd <AstrBot 数据目录>/data/plugins
git clone https://github.com/iownmmiku/astrbot_plugin_astrcraft.git
```

或者手动复制：把仓库**根目录的 `.py` 文件 + `metadata.yaml` + `_conf_schema.json` + `skills_docs/`**
放进 `<AstrBot 数据目录>/data/plugins/astrbot_plugin_astrcraft/`。

然后在 AstrBot 里**重载插件**。

> **不需要装任何 Python 依赖**——插件只用 AstrBot API + 标准库。
> 只有 Node 引擎需要 `npm install`（下一步）。

### 2. 装引擎依赖

引擎是独立的 Node 进程，需要先装依赖（只需一次）：

```bash
cd engine
npm install
```

### 3. 告诉插件引擎在哪

在 AstrBot 的插件配置里把 **`engine_dir`** 指向 `engine/` 的绝对路径。

### 4. 开一个服务器

它默认用**离线账号**，所以服务器要设 `online-mode=false`。
改 `server.properties` 后重启服务器。

### 5. 进服

在 AstrBot 里发指令：

```
mc进服
```

看到 `机器人已进服：xxx @ 1.20.1` 就成了。

> **注意：默认不会自动进服**（`auto_connect` 默认关——避免第一次装上时服务器地址还没填就乱连）。
> 确认能正常进服之后，可以在插件配置里把它打开。

### 6. 让它干活

游戏里直接跟它说话（**消息里要带它的名字**，比如 `纱雾` 或你在配置里设的名字）：

```
纱雾，砍点木头回来
纱雾，盖个小屋
纱雾，挖 10 个铁矿
纱雾，跟着我
```

## 常用指令

| 指令 | 作用 |
|---|---|
| `mc进服` / `mc退服` | 让它进 / 退服务器 |
| `mc状态` | 位置、血量、饱食、背包 |
| `mc她在干嘛` | 她现在的打算、心情、最近做过的事 |
| **`mc诊断`** | **她为什么不动 / 卡在哪 / 在等什么**——排查问题先看这个 |
| `mc记忆` | 她记得的事 |
| `mc帮助` | 全部指令 |

## 它是怎么工作的

```
AstrBot（Python 插件）
   │  ① 提供 LLM 工具（50+）：模型通过这些工具驱动它
   │  ② 「过日子」循环：没人指挥时，它自己观察 → 决定 → 动手
   │
   │  NDJSON / JSON-RPC 2.0（stdio）
   ▼
Node 引擎（mineflayer）
   │  ③ 真实客户端：物理、区块、背包、合成、寻路
   │  ④ 本能层：溺水 / 岩浆 / 着火 / 进食 / 反击 / 坠落在本地处理，不花 token
   │  ⑤ 技能层：砍树 / 挖矿 / 熔炼 / 盖房 / 图纸建造
   ▼
Minecraft 服务器
```

**为什么分两个进程**：两边都用各自生态里最成熟的东西，而不是互相迁就。
引擎的 stdout 只走协议、日志全走 stderr，所以插件和引擎可以分别重启、互不干扰。

**关于"走路不改动世界"**：寻路默认不会拆地形（墙、地板、别人的房子都原样不动），
只有软植被（树叶/草丛）会蹭掉——真人穿过树叶也不会停下来。
走不通时它会**如实失败并告诉你"要挖哪几格"**，把"要不要动世界"这个决定交给模型。

```
<仓库根目录> = 插件本体（AstrBot 要求 metadata.yaml / main.py 在根目录）
  main.py            插件主体、引擎生命周期、事件转发
  life.py            「过日子」循环：观察 → 决定 → 行动
  action_agent.py    ReAct：让模型用工具直接驱动它
  knowledge.py       知识库：攻略 + 它自己的教训 + 世界笔记
  advisor.py         生存顾问：按阶段给建议（缺什么、下一步做什么）
  llm_tools_*.py     50+ 个 LLM 工具
  skills_docs/       攻略（Markdown，模型按需读）

engine/              Node 引擎（mineflayer）
  bot.js             引擎主体、本能层、诊断视图
  movement.js        寻路、卡住脱困、悬崖保护
  actions.js         挖掘/放置/合成/熔炼/容器
  skills/            技能：砍树、挖矿、建造、蓝图、采集…
  stations.js        工作站记忆
  humanize.js        拟人化：渐进转头、变速行走、空闲环顾

dev-tools/           开发用的测试与探针（**不参与运行**，可删）
docs/                详细文档（能力边界、安装、模块图）
```

## 已知问题

这一节是**如实告知**，不是免责声明。完整清单见 [docs/LIMITS.md](docs/LIMITS.md)。

| 问题 | 表现 | 现状 |
|---|---|---|
| **复杂地形长距离寻路** | 在起伏大的丛林里可能"找不到路、原地不动" | 超平坦世界稳定通过；引擎会**如实报错并给出"要挖哪几格"**，不会假装到达 |
| **合成偶发失败** | 约 1/6 的运行里，**合成工作台**这一步失败 | mineflayer ↔ 服务端窗口状态机的固有脆弱点；有 3 轮复位重试兜底，失败会如实报错 |
| **从高处坠落的自救** | 能检测到（下落速度判断准确），但**倒水/垫方块在服务端不被接受** | **未解决**。建议靠提前预防：`mc_check_danger` 能扫出悬崖和岩浆 |
| **正版账号登录** | 默认走离线账号 | 正版需要额外配置，**未端到端验证** |
| **模组服** | 只支持原版 / Paper / Spigot 类服务端 | mineflayer 需要模组注册表适配，工作量大 |
| **每步都要过一次模型** | 模型慢 → 它的反应就慢 | 这是"LLM 真正控制角色"的代价；换更快的模型端点最有效 |

## 常见问题

**进服失败？**
服务器要 `online-mode=false`；检查插件配置里的地址/端口；`mc诊断` 会告诉你卡在哪。

**它不动？**
先 `mc诊断`——它会直接说清"为什么不动"（没连接 / 引擎被卡住 / 有任务卡着 / 在等模型）。
最常见的原因是**没重载插件或没重启引擎**，改动不会自动生效。

**能进别人开的服吗？**
能，只要那个服 `online-mode=false`。它是服务端的真实玩家，动作由服务端校验。

**它会不会乱拆我家？**
不会。走路默认不动世界；挖方块要走 `mc_mine` 这类工具，而且它只在需要时才挖。

**模型要花多少钱？**
用你自己的 key。一次典型任务（砍树 → 做工具）通常几分钱。
模型越快，它的反应越顺——每走一步都要过一次模型。
