# Astrcraft

**让 AstrBot 的机器人在 Minecraft 里像一个真玩家那样自己过日子。**

不是"会聊天的 NPC"，也不是"瞬移 + 秒破方块"的脚本。它是个服务端眼里的**真实玩家**：
原版物理、区块解析、背包/合成/熔炼，每个动作都由服务端逐条校验——
和红石、怪物 AI、别人的建筑站在同一套规则里。

```
你：    砍点木头回来，顺便做个工作台
Astrcraft：嗯，这就去。
        ▸ 砍树 ×8 → 木板 ×16 → 工作台 → 放下 → 木棍 ×4 → 木镐
Astrcraft：木头砍够了，工作台也摆好了，镐子也顺手做了。
```

## 它能做什么

| | |
|---|---|
| ⛏️ **干活** | 砍树、挖矿（找矿脉）、采集、合成、熔炼、把战利品塞进箱子 |
| 🏠 **盖房子** | **照着图纸盖**——图纸由模型自己画（字符网格 + 调色板），能盖出有窗、有屋檐、有隔断的房子，而不是只会盖方盒子 |
| 🧭 **走位** | 真寻路：绕障碍、上下台阶、跳下落地、**走路不改动世界**；走不通时列出"要挖哪几格、要不要垫脚"的候选路线，由模型决定值不值得动世界 |
| 🕳️ **脱困** | 掉进 2 格以上的坑/竖井能自己爬出来：挖台阶 → 垫脚上升（跳起来往脚下放方块）→ 侧向开洞，依次试，做不到会**如实说为什么** |
| 🧱 **改造地形** | **铺路**（往前逐格垫方块跨过坑/沟，遇到岩浆会停下来说）、**垫高自己**（垂直往上）、**挖通一条路**（把挡路的方块真的挖掉再走过去） |
| ⚔️ **战斗** | 近战、躲怪、快淹死自己上浮、血量低了自己后撤 |
| 🔭 **感知** | 扫方块、扫实体、查状态、查配方、看世界时间与天气、**动手前先扫一遍附近有没有岩浆/悬崖** |
| 🍞 **过日子** | 饿了吃、没吃的去打猎、天黑了点灯、晚上回屋、从高处坠落会自救 |
| 💀 **死了会重建** | 死后自动丢掉旧打算 + 写一份恢复清单（先砍树 → 做工作台和木镐 → 有镐了挖石头 → 再想死前那件事）；**回去捡掉落物会判断值不值得去**（掉落物约 5 分钟消失，太远就劝你别去） |
| 👂 **干活时也听得到你** | 它跑长任务时你说的话**不会丢**——话进队列，等它到安全点（下次动手前）会看到；受伤/饿了/工具坏了也会进队列 |
| 🧠 **会积累经验** | 攻略（人写的）+ **教训（它自己从失败里总结的）** + 世界笔记；同一个坑摔三次就会记下"下次该怎么做" |
| 🗺️ **会记路** | 记住用过的箱子/熔炉/工作台在哪，下次直接走回去用，而不是重做一个 |
| 💬 **聊天** | 游戏内聊天转发到 QQ/TG；游戏里提到它的名字，它会用人格接话 |
| 🔍 **看得见它在干嘛** | `mc状态` 直接说清"**它为什么没在动**"（死了/没进服/引擎挂了/被暂停/模型不可用）+ 队列里排着什么 + **用量台账**（上一轮的缓存命中率） |

**LLM 是真的在控制它**：63 个工具（移动 / 挖掘 / 放置 / 战斗 / 合成 / 扫描 / 容器 / 图纸 / 脱困 / 铺路…），
模型一步步决定做什么；工具返回什么就读懂什么，换个做法再来。

**它知道的 = 它能做的**：仓库里有一个 `check_capabilities.py` 检查器，
专门拦住"提示词说会做、代码里其实没有"这类问题——
已经抓到过三次（一个不存在的工具、以及两个"知道该垫方块/该回去捡但没这能力"）。

## 快速开始

### 1. 装插件

**可以直接把整个仓库克隆进插件目录**（仓库根目录就是插件本体，`metadata.yaml` / `main.py` 都在根上）：

```bash
cd <AstrBot 数据目录>/data/plugins
git clone https://github.com/iownmmiku/astrbot_plugin_astrcraft.git
```

或者手动复制：把仓库**根目录的 `.py` 文件 + `metadata.yaml` + `_conf_schema.json` + `skills_docs/`**
放进 `<AstrBot 数据目录>/data/plugins/astrbot_plugin_astrcraft/`。

然后在 AstrBot 里**重载插件**。

> **不需要装任何 Python 依赖**——插件只用 AstrBot API + 标准库。
> 只有 Node 引擎需要 `npm install`（下一步）。

### 2. 装引擎依赖

引擎是独立的 Node 进程，需要先装依赖（只需一次）：

```bash
cd engine
npm install
```

### 3. 告诉插件引擎在哪

在 AstrBot 的插件配置里把 **`engine_dir`** 指向 `engine/` 的绝对路径。

### 4. 开一个服务器

它默认用**离线账号**，所以服务器要设 `online-mode=false`。
改 `server.properties` 后重启服务器。

### 5. 进服

在 AstrBot 里发指令：

```
mc进服
```

看到 `机器人已进服：xxx @ 1.20.1` 就成了。

> **注意：默认不会自动进服**（`auto_connect` 默认关——避免第一次装上时服务器地址还没填就乱连）。
> 确认能正常进服之后，可以在插件配置里把它打开。

### 6. 让它干活

游戏里直接跟它说话（**消息里要带它的名字**，比如 `纱雾` 或你在配置里设的名字）：

```
纱雾，砍点木头回来
纱雾，盖个小屋
纱雾，挖 10 个铁矿
纱雾，跟着我
```

## 常用指令

| 指令 | 作用 |
|---|---|
| `mc进服` / `mc退服` | 让它进 / 退服务器 |
| `mc状态` | 位置、血量、饱食、背包 |
| `mc她在干嘛` | 她现在的打算、心情、最近做过的事 |
| **`mc诊断`** | **她为什么不动 / 卡在哪 / 在等什么**——排查问题先看这个 |
| `mc记忆` | 她记得的事 |
| `mc帮助` | 全部指令 |

## 它是怎么工作的

```
AstrBot（Python 插件）
   │  ① 提供 LLM 工具（63 个）：模型通过这些工具驱动它
   │  ② 「过日子」循环：没人指挥时，它自己观察 → 决定 → 动手
   │  ③ 输入队列：你说的话 + 世界事件（受伤/饿了/工具坏）排在这里，
   │     等它到安全点（下次动手前）再注入——所以它干活时说话也不会丢
   │
   │  NDJSON / JSON-RPC 2.0（stdio）
   ▼
Node 引擎（mineflayer）
   │  ③ 真实客户端：物理、区块、背包、合成、寻路
   │  ④ 本能层：溺水 / 岩浆 / 着火 / 进食 / 反击 / 坠落在本地处理，不花 token
   │  ⑤ 技能层：砍树 / 挖矿 / 熔炼 / 盖房 / 图纸建造
   ▼
Minecraft 服务器
```

**为什么分两个进程**：两边都用各自生态里最成熟的东西，而不是互相迁就。
引擎的 stdout 只走协议、日志全走 stderr，所以插件和引擎可以分别重启、互不干扰。

**关于"走路不改动世界"**：寻路默认不会拆地形（墙、地板、别人的房子都原样不动），
只有软植被（树叶/草丛）会蹭掉——真人穿过树叶也不会停下来。
走不通时它会**如实失败并告诉你"要挖哪几格"**，把"要不要动世界"这个决定交给模型。

## 已知问题与限制

这一节是**如实告知**，不是免责声明。完整清单见 [docs/LIMITS.md](docs/LIMITS.md)、
优化审计见 [docs/OPTIMIZATION_AUDIT.md](docs/OPTIMIZATION_AUDIT.md)。

### 一、最影响体验的一条：它"想"得慢

**这是目前最大的短板，而且用户实测反馈过**（"每次停下来思考的时间太长了，动作也不够流畅"）。

| | |
|---|---|
| **一次决策最多 6 轮模型往返** | 每轮都是一次完整的模型调用（几秒）。她在两次动手之间就是**站着等模型** |
| **每轮都要发 12,742 字符的工具说明** | 63 个工具的 schema 每次都发一遍；模型的首字延迟随输入增长 |
| **每轮还要发 2,223 字符的操作规则** | 理论上缓存能命中，但取决于你的 provider 支不支持 |

**为什么会这样**：这是"**LLM 真正控制角色**"的固有代价——她不是脚本，
每一步都是模型现场决定的。**换更快的模型端点是最有效的办法**。

**已经在做的缓解**：
- 提交长任务后**立刻结束这一轮**（不会反复问"做完了吗"）
- 有计划时**直接执行下一步、不调模型**
- 没有任何事做时**立刻重新决策**，不等固定间隔

**还没做、但知道该往哪做的**：
- 工具说明太长（12,742 字符）——但它是模型唯一的说明书，**砍了会伤质量**，
  所以需要一次真实运行的数据来决定怎么砍（见 OPTIMIZATION_AUDIT.md 的 P1）
- 仓库里加了**分段计时**：每次决策会打一行
  `决策耗时：准备 ___ms + 模型 ___ms = 共 ___ms；提示词 ___ 字符，本轮调了 _ 次工具`
  —— 拿这行数据就能定位到底慢在哪一段

### 二、能力上的明确边界

| 问题 | 表现 | 现状 |
|---|---|---|
| **从高处坠落的自救（MLG）** | **检测可用、动作不可靠**：能准确判断"正在下坠、还有几格落地"，但倒水/垫方块在服务端**经常被拒** | **部分完成**——见 [docs/LIMITS.md](docs/LIMITS.md) 的「MLG 排查记录」。实际保命靠**提前预防**（悬崖保护 + `mc_check_danger`） |
| **复杂地形长距离寻路** | 在起伏大的丛林里可能"找不到路、原地不动" | 引擎会**如实报错**并说清病因（比如"**你比周围地面低 2 格，跳不上去，用 mc_climb_out**"），不会假装到达 |
| **合成偶发失败** | 约 1/6 的运行里，**合成工作台**这一步失败 | mineflayer ↔ 服务端窗口状态机的固有脆弱点；有 3 轮复位重试兜底 |
| **正版账号登录** | 默认走离线账号 | 正版需要额外配置，**未端到端验证** |
| **模组服** | 只支持原版 / Paper / Spigot 类服务端 | mineflayer 需要模组注册表适配，工作量大 |

### 三、实现上"够用但不够漂亮"的地方（诚实标注）

| 项 | 现状 | 为什么这样 |
|---|---|---|
| **"身体层"不是真正的每 tick 竞价** | 现在是 **200ms 反射层 + 出价表 + 优先级队列**；抢占是"取消 + 重新排队"，**不是挂起/恢复** | 跨进程做不到进程内每 tick 同步推进；技能是普通 async 函数，被打断后没有恢复点。好在技能大多是"按背包里已有的数量算差值"，重跑不白费 |
| **"箱子满了"靠报错文本匹配** | 引擎侧**没有"箱子满了"这个状态**，只能从服务端报错里认（"container is full"/"没有空间"/"装不下"） | 认不出就不报——**宁可漏报，也不要把"附近没有箱子"误判成"满了"** |
| **"工具坏了"靠两拍比较** | 每 200ms 比较"手上拿的工具"这一拍和上一拍：快坏了 → 消失了 → 背包里也没了 | **mineflayer 根本没有 `itemBreak` 事件**（实测确认）。判据故意保守，**宁可漏报不误报** |
| **agent 路径不产出"计划"** | "有计划就直接执行下一步、不调模型"这条**只在旧路径（`decide()`）下生效** | 走 agent 路径时每轮仍要过一次模型。**这是已知的、没做的事** |
| **反射层是 200ms，不是每 tick** | 本能最坏延迟 200ms | 试过提到更快，但脱困逻辑里有一串按秒调的时间常数，**提速会打破已验证的行为**（详见 `docs/BODY_LAYER.md` 的 S1） |

### 四、测试自身的稳定性（不影响功能，但影响判断）

| 测试 | 现状 |
|---|---|
| `test_unstuck` | 曾经 60~80% 通过（测试自己对时序敏感，不是功能问题）；修完后连跑 6 次 6/6 |
| `test_pathfinding` | 曾经稳定 5/6（"绕墙"）；查下来是**真 bug**（她到了却被告知失败），修完连跑 2 次 6/6 |
| `minetest` | 偶发 12/13，**未深查** |

**说明**：这些是**测试的不稳定**，不是功能的不稳定——但一个 60% 的测试没法用来判断任何改动，
所以修测试本身也是有价值的工作。

### 五、明确不支持的

- **多机器人**：一个插件实例控制一个机器人
- **模组方块/实体**：只认原版注册表
- **语音**：只有文字聊天
- **它不会替你玩游戏**：它过自己的日子，你说话它会听，但它有自己的打算

## 我装对了吗 / 我改对了吗

**一条命令跑全部检查**（不需要 AstrBot、不需要服务器，约 3 分钟）：

```bash
python dev-tools/run_all.py
```

它会跑 42 个脚本里**不需要服务器**的那些（31 个），并**明确告诉你跳过了什么**：

```
✅ 通过 31    ❌ 失败 0    ⏭️ 跳过 4（需要 AstrBot 运行时）
⏭️  另有 7 个需要服务器的**没跑** —— 要测的话先起测试服，再 --full
```

**加了 `--full` 连需要测试服的也跑**（先起一台 MC 服务器在 25566、RCON 25576）：

```bash
python dev-tools/run_all.py --full
```

**它还会标出"已知会偶发红"的脚本**（比如 `test_survival_chain` 首次运行常 2/3，
是冷启动、区块没就绪，重跑即好）—— 这样你不会去追一个不存在的 bug。

> 想只跑某几个：`python dev-tools/run_all.py --only life`
> 想看完整输出：`python dev-tools/run_all.py -v`

**装引擎依赖**（只需一次，在 `engine/` 里）：

```bash
cd engine && npm install
```

> **关于体积**：完整 `npm install` 约 770 MB —— 其中 `minecraft-data` 占 427 MB
> （mineflayer 需要全版本数据，躲不掉）。
>
> **不用观战窗口的话可以省 300 多 MB**：`prismarine-viewer` / `express` / `socket.io`
> 已经改成**可选依赖**（观战窗口默认就是关的），所以：
>
> ```bash
> cd engine && npm install --no-optional
> ```
>
> 装了也白装不了 —— 开观战窗口时如果缺依赖，引擎会告诉你**该装什么**，不会静默失败。

## 常见问题

**进服失败？**
服务器要 `online-mode=false`；检查插件配置里的地址/端口；`mc诊断` 会告诉你卡在哪。

**它不动？**
先 `mc诊断`——它会直接说清"为什么不动"（没连接 / 引擎被卡住 / 有任务卡着 / 在等模型）。
最常见的原因是**没重载插件或没重启引擎**，改动不会自动生效。

**能进别人开的服吗？**
能，只要那个服 `online-mode=false`。它是服务端的真实玩家，动作由服务端校验。

**它会不会乱拆我家？**
不会。走路默认不动世界；挖方块要走 `mc_mine` 这类工具，而且它只在需要时才挖。

**模型要花多少钱？**
用你自己的 key。一次典型任务（砍树 → 做工具）通常几分钱。
模型越快，它的反应越顺——每走一步都要过一次模型。
