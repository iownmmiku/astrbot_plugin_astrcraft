# Astrcraft

**v1.3.2 · AstrBot 的 Minecraft 自主游玩插件**

让 AstrBot 的机器人以真实玩家身份进入 Minecraft：观察环境、安排工作、采集资源、制作工具、建造基地，并在饥饿、受伤或遇险时调整行动。

项目目标是能够自主、连贯地生存与建设。目前已经验证多条实际生存链，开放世界长期自主生存仍需要持续实测。使用中发现卡住、重复动作或结果不符，欢迎提交 [Issue](https://github.com/iownmmiku/astrbot_plugin_astrcraft/issues)。

[下载发布版](https://github.com/iownmmiku/astrbot_plugin_astrcraft/releases/latest) · [更新日志](CHANGELOG.md) · [本轮修复与验证记录](docs/UPDATE_2026-10-08.md) · [此前生存验证](docs/SURVIVAL_2026-10-02.md)

## 她能做什么

| 能力 | 当前行为 |
|---|---|
| 自主工作 | 没有主人指派任务时，观察状态并决定采集、补给、建设等工作；已有计划按步骤连续执行 |
| 采集与制作 | 砍树、采石、采矿、收集指定物品；按缺口准备木板、木棍、工作台、工具与熔炉 |
| 农田采收 | 只收成熟小麦、胡萝卜、马铃薯与甜菜；有种子时补种，按补种后的净产出计数 |
| 生存补给 | 优先吃随身食物、加工已有食材或使用近处基地储备；补给后继续原目标 |
| 基地生活 | 记录房屋、床、箱桶和工作站；实际进屋、关门、睡觉、存取物资，再出门继续工作 |
| 采矿返程 | 采到材料后检查退路；返程失败保留实物，先有限脱困，确认站稳后接回后续计划 |
| 工具维护 | 按矿物要求选择镐；中途断镐时尝试用随身材料补造，并补回制作消耗的目标建材 |
| 建设与移动 | 寻路、庇护所、字符图纸建造、铺路、垫高和挖通道；自主采料与脱困保护已登记基地 |
| 应急处理 | 自动进食、残血后撤、溺水上浮和近身反击；急停会取消当前动作 |
| 交流与记忆 | 游戏内聊天、AstrBot 会话订阅、人格、经历、教训和按服务器/维度隔离的地点记忆 |

动作由 Mineflayer 客户端执行，服务器校验移动、挖掘、放置、合成和背包变化。是否完成以实际位置、物品和世界状态验收。

## 安装与启动

### 1. 准备运行环境

| 项目 | 要求 |
|---|---|
| AstrBot | 声明兼容 `>=4.17,<5`，配置好可用的模型提供方 |
| Node.js | **22 或更高版本**；当前锁定的 Mineflayer 依赖要求 Node.js 22+ |
| Minecraft | Java 版服务器；当前实服验证环境为 Paper 1.20.1 |
| 登录 | 默认 `offline`，连接的服务器需要 `online-mode=false` |

Node.js 和 npm 必须能在 **AstrBot 实际运行的环境**中执行。AstrBot 在容器中运行时，需要在容器内安装依赖。连接已有 Minecraft 服务器无需在 AstrBot 环境中安装 Java。

### 2. 安装完整插件

可在 AstrBot 插件管理中安装本仓库，或从 [Releases](https://github.com/iownmmiku/astrbot_plugin_astrcraft/releases) 下载 `astrbot_plugin_astrcraft-v1.3.2.zip`。

手动安装时，将 ZIP 解压到：

```text
<AstrBot 数据目录>/data/plugins/astrbot_plugin_astrcraft/
```

插件目录中应直接出现：

```text
astrbot_plugin_astrcraft/
├── main.py
├── metadata.yaml
├── _conf_schema.json
├── 其它 Python 模块
├── .astrbot-plugin/i18n/
├── pages/control/
├── skills_docs/
└── engine/
    ├── index.js
    ├── package.json
    ├── package-lock.json
    └── skills/
```

也可克隆整个仓库：

```bash
git clone https://github.com/iownmmiku/astrbot_plugin_astrcraft.git
```

仓库根目录就是插件本体，安装时保留完整的 `engine/` 和 `skills_docs/`。
使用网页控制台时还需要保留 `pages/`、`.astrbot-plugin/` 和 `webui_server.py`。

### 3. 安装引擎依赖

在插件的 `engine/` 目录执行：

```bash
node --version
npm ci
```

发布 ZIP 包含源码与依赖锁文件，`node_modules` 由上述命令在运行环境中安装。Python 侧使用 AstrBot API 与标准库。

### 4. 填写插件配置

| 配置项 | 设置 |
|---|---|
| `server_host` / `server_port` | Minecraft 地址与端口，默认 `127.0.0.1:25565` |
| `mc_version` | 与服务器版本一致，默认 `1.20.1` |
| `bot_username` | 游戏内名字，默认 `AstrBot` |
| `auth_method` | 默认 `offline`；Microsoft 登录尚未完成端到端验证 |
| `engine_dir` | 留空自动使用插件内的 `engine/`；外置部署时填写引擎绝对路径 |
| `node_path` | 留空自动探测；找不到 Node 时填写可执行文件绝对路径 |
| `enable_life_loop` / `auto_mode` | 保持开启，让她自主生活与行动 |
| `auto_eat` / `auto_defend` | 默认开启，自动进食与近身反击 |
| `auto_connect` | 默认关闭，首次确认配置与进服正常后可开启 |

人格优先使用 AstrBot 人格库；可用 `mc_persona_id` 指定人格，或通过 `mc人格` 切换。全部配置见 [_conf_schema.json](_conf_schema.json)。

### 5. 重载插件并进服

在 AstrBot 中重载插件，然后发送：

```text
mc进服
mc状态
mc她在干嘛
```

保持自主生活开启，进服后她会根据状态安排工作。需要明确任务时，可发送 `mc目标 采集 8 个圆石`，或在游戏聊天中带上她的名字，例如 `AstrBot，砍 4 根木头`。

## WebUI 网页控制台

中文控制台包含世界总览、行动与目标、随身背包、世界记录四个页面，适配桌面、手机及 AstrBot 亮暗主题。能查看真实血量、饱食、位置、经验、环境、自主打算、等待原因、目标步骤与引擎队列；支持进服、退服、暂停、继续、急停、目标指派与游戏发言。

默认采用 [AstrBot 官方 Plugin Pages](https://docs.astrbot.app/dev/star/guides/plugin-pages.html) 格式：

1. 保持 `enable_webui=true`、`webui_mode=astrbot`，重载插件。
2. 打开 **AstrBot 管理面板 → 插件 → Astrcraft 插件详情 → Astrcraft 控制台**。
3. 通过已有 AstrBot 登录会话操作，无需额外控制台令牌或映射 `3008` 端口。`mc控制台` 会提示入口位置。

页面使用 `pages/control/index.html`、官方 bridge 和插件 Web API，凭据由 AstrBot 管理。此功能需要支持 Plugin Pages 的 AstrBot 后端与管理面板；声明的基础插件兼容范围不代表旧面板已具有 Pages。缺少入口时更新 AstrBot 和管理面板，或使用下方独立模式。升级前曾关闭 `enable_webui` 的配置仍需手动开启。

| 配置项 | 默认值与作用 |
|---|---|
| `enable_webui` | `true`，启用控制台接口，修改后重载插件 |
| `webui_mode` | `astrbot`，原生 Pages；`standalone` 使用独立 HTTP 服务 |
| `webui_host` | 仅独立模式使用；默认 `127.0.0.1`，容器/局域网可设 `0.0.0.0` |
| `webui_port` | 仅独立模式使用；默认 `3008`，与 3D 观战端口 `3007` 独立 |
| `webui_token` | 仅独立模式使用；留空自动生成并持久保存，或填写长随机 ASCII 令牌 |

独立模式重载后访问 `http://127.0.0.1:3008`，管理员在**私聊**发送 `mc控制台` 获取令牌；群聊只返回地址，数据目录的 `webui_token.txt` 也保存自动生成的令牌。容器部署映射控制台端口，例如 `3008:3008`。公网使用 HTTPS 反向代理，保留原始 `Host`、转发 `Authorization`，将控制台放在域名根路径。修改令牌后重载插件，旧令牌立即失效。浏览器只在当前标签页会话中保存令牌，退出会清除；迟到请求不能重新填回私有状态。

控制台每 2 秒同步，后台标签页降为每 10 秒；多窗口共享 1 秒引擎快照缓存。读取失败明确显示未知或同步中断。进服和目标规划有异步回执；急停和退服可中断普通操作，退服等待期间仍可急停，失败不会自动重放。回执过期会释放界面的等待状态并明确提示。

模型用量区区分自主行动、目标规划、环境侦察和游戏聊天，展示请求数量、提供方已报告 Token 与模型等待时间。未报告用量明确标为未知；缓存输入只计算一次，不估算费用。

网页无需前端依赖或打包；引擎启动失败时仍可查看诊断并尝试进服。3D 观战仍需可选 Node 依赖与可访问的观战端口。原生 Pages 沙箱限制弹窗，因此开启观战后显示可选中复制的完整地址，在浏览器中打开；独立模式可直接打开观战链接。营地插画与物品类别图标是界面示意，实际世界画面由观战服务提供。

## 常用指令

| 指令 | 作用 |
|---|---|
| `mc进服` / `mc退服` | 连接或退出服务器 |
| `mc急停` / `mc继续` | 停止全部行动；恢复当前目标或自主生活 |
| `mc目标 <描述>` / `mc进度` | 指派目标与查看进度 |
| `mc暂停` / `mc放弃` | 暂停目标和自主行动、取消当前动作；或放弃目标并恢复自主生活 |
| `mc状态` | 查看位置、身体、背包与任务 |
| `mc她在干嘛` | 查看打算、自主行动和等待原因 |
| `mc诊断` / `mc调试` | 排查引擎、模型、任务队列和事件 |
| `mc记忆` / `mc心情` / `mc人格` | 查看记忆、心情或切换人格 |
| `mc订阅` / `mc退订` | 将游戏聊天与动态转发到当前会话 |
| `mc开观战` / `mc看她` | 开启或查看可选的浏览器观战 |
| `mc控制台` | 原生模式提示管理面板入口；独立模式返回地址，管理员私聊可获取令牌 |
| `mc帮助` / `mc技能` | 查看指令与技能列表 |

管理类指令受 AstrBot 管理员权限控制。观战需要开启 `enable_viewer`，并安装对应可选引擎依赖。

## 自主行动如何衔接

1. 模型提出目标或计划，Python 生活循环检查最新身体、材料、主人指令与世界状态。
2. Node 引擎执行采集、制作、移动等技能，按服务端实际结果报告产物与位置。
3. 完成通知唤醒下一步；已有计划正常推进时不再请求模型。
4. 饥饿、残血、缺料、背包将满或返程未完成时，先处理对应生存步骤，再接回仍有效的原参数。
5. 新主人指令、急停、重生或切换世界使旧任务与旧回复失效，重新观察后再行动。

现有材料可在确认关门的完整基地内加工；缺料的屋外工作先检查昼夜、血量与实际出门。补给反复失败有冷却与有限重试，新物资和可验证工作站可恢复尝试，单纯等待或更饿不会无限重置预算。

模型可通过 `mc_plan_do` 一次安排多步，步骤支持带参数的 JSON 数组，例如：

```json
[
  {"skill": "chop_tree", "params": {"count": 4}},
  {"skill": "make_tools", "params": {"tier": "wooden", "kinds": ["pickaxe"]}},
  {"skill": "mine_stone", "params": {"count": 8}}
]
```

新决策仍受模型响应速度影响。既定计划与部分规则补给可以减少模型往返，不能消除生产模型的网络延迟。

## 1.3.2 本次更新

- **AstrBot 原生控制台**：官方 Pages 目录、bridge、登录会话与插件 API；独立 HTTP 模式保留，手机和亮暗主题可用。
- **目标连续执行**：旧规划失效、单循环推进、暂停不消耗失败次数；砍树、采矿、采石恢复原追加数量与矿口，`collect` 按原库存目标补缺。修复圆石目标选错技能及重连后自主循环保持暂停的问题。
- **成熟作物与地形**：四类作物保护幼苗、成熟收割后补种，按净产出继续；搜作物在地表行走。树冠、树干、坡地与有出口的开放山谷不再轻易触发地下救援。
- **用量与评测**：模型请求统一计数，缓存 Token 去重，失败/取消的等待也记录；新增使用真实模型、生产自主组件的持续生存评测工具。
- **网页控制竞态**：急停前尚未开始的任务也有终态，退服期间可以急停；过期回执和迟到登录响应不会锁住操作或恢复旧会话。

## 当前限制与排查

- **长期自主生存**：仍需真实模型与自然世界持续评测，复杂洞穴、远距离地形和自行准备全部退路材料尚未充分验证。
- **高处坠落自救**：倒水或垫方块的时机仍不可靠，当前主要依靠提前检查悬崖与危险落脚点。
- **服务器兼容**：当前验证以 Paper 1.20.1 为主；其他版本、模组服、正版账号与严格反作弊配置需要分别验证。
- **建筑保护**：自主采料与脱困保护同世界已登记基地；其他玩家建筑仍需要合理配置挖掘白名单、黑名单与出生点保护。

| 现象 | 先检查 |
|---|---|
| 引擎未运行 | Node.js 是否达到 22+、`engine/` 是否完整、`npm ci` 是否执行成功、`engine_dir` 与 `node_path` 是否正确 |
| 无法进服 | 地址、端口、`mc_version` 与服务器是否一致；离线登录与服务端认证设置是否匹配 |
| 不行动或反复等待 | `mc诊断`、急停状态、自主开关、模型是否可用，以及身体状态与技能冷却原因 |
| 更新后行为没变化 | 重载插件，确认 Python 和 Node 使用同一版本目录；外置 `engine_dir` 也需同步更新 |

升级前备份插件配置与记忆数据。数据位置由 `datadir.py` 解析，可查看初始化日志或运行期的 `data_location.json`；安装包不包含个人运行数据。

反馈问题时请附上版本、服务器类型/版本、`mc诊断` 输出、复现步骤和相关日志。更多边界见 [LIMITS.md](docs/LIMITS.md)。
